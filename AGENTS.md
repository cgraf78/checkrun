# AGENTS.md

## About

`checkrun` owns formatter, linter, and file-check dispatch for the
`checkrun`, `autoformat`, and `autolint` CLIs. Callers own *when* those
semantics run. The cross-surface contract is
[docs/workflow-contract.md](docs/workflow-contract.md).

## Layout

- `share/checkrun/registry.json` is the durable source of filetype,
  phase, and tool-selection vocabulary. Do not duplicate those rules
  in adapters, editors, or hooks.
- `lib/checkrun/` owns the implementation. `bin/` entry points are
  thin dispatchers.
- `lib/checkrun/registry.py` interprets the registry for `plan`,
  `explain`, and capabilities.
- `lib/checkrun/verify.py` owns explicit project analyzers (Go/Rust/C++
  owner-root checks). Keep those off the save-time lint path.
- `lib/checkrun/linters/` groups shell adapters by tooling domain.

## Invariants

- `checkrun lint`, `checkrun check`, and `autolint` are one fast
  automatic path. Registry lint adapters must stay file-scoped
  (`executionScope: "file"`).
- Broader, slow, or project-scoped analyzers belong in
  `checkrun verify` or a caller-owned Sley verify workflow.
- Missing optional language tools are graceful no-ops.
- `autoformat` mutates eligible files and exits 0 even when a
  formatter fails, so save-time hooks can surface stderr without
  blocking.
- Tool config contents (`ruff.toml`, ignore files, schema association
  policy) are owned by dotfiles or the project repo, not by Checkrun.

## Testing

- `test/checkrun-test` is the local and CI entry point. It runs the
  cancellation, hook-performance, and runner suites alone first, then the
  rest with `CHECKRUN_TEST_JOBS` workers (default 4).
- It requires Python 3.11+ (`CHECKRUN_PYTHON` overrides) and yq v4.
- Missing backends skip locally, so a local green run does not prove adapter
  behavior. CI installs every backend through mise from
  `.github/mise/checkrun-ci.toml`, locked by `.github/mise/mise.lock`
  (except on the Alpine leg).
- Termux CI runs only `install-test`, `path-policy-test`, `registry-test`, and
  `CHECKRUN_HOOK_PERF_STRUCTURAL_ONLY=1 hook-performance-test`.
- Registry changes need registry-level coverage plus one behavior test of the
  derived plan or output; the README's "To add a formatter or linter" steps
  are the recipe.

## Test isolation

- `test/checkrun-test` unsets `BASH_ENV` and `ENV`. `test/helpers.sh` points
  `CHECKRUN_CONFIG_DIR` at a temp dir and drops the `CHECKRUN_*` knobs that
  redirect a run (it keeps `CHECKRUN_PYTHON`). New suites source it.

## CI and generated files

- `test/checkrun-test` runs no ShellCheck. CI's ShellCheck job fails on any
  shell program missing from `test/shellcheck-files.txt` (untracked files
  included) and on stale rows. Before pushing, run
  `bash <actions@lock>/.github/actions/shellcheck-inventory/run.sh "$PWD" test/shellcheck-files.txt`.
- `install.sh` is generated by the cgraf78/actions checkout-installer and
  byte-checked by `actions-sync`. Edit `scripts/checkout-installer.conf`, then
  run `consumer-ci/sync.sh <this checkout>` from cgraf78/actions at the
  locked SHA.
- `.github/cgraf78-actions.lock` and every `uses: cgraf78/actions/...@sha`
  move together, only via `consumer-ci/sync.sh`.
- `test/suites/ci-toolchain-test` pins text in all four workflows and the
  mise lock; edit it together with any workflow change.
- Don't hand-edit `.github/mise/mise.lock`. A weekly bot refreshes it, and
  `python3 .github/scripts/verify_mise_lock.py .github/mise/checkrun-ci.toml .github/mise/mise.lock`
  verifies it.
- `retry-infrastructure.yml` triggers on the workflow named `Tests`; don't
  rename it.
- Every `bin/*` command needs a man page (`test/suites/manpage-test`).
- sley's `vscode-vocab-sync-test` reads `editorLanguageIds` from
  `share/checkrun/registry.json`, so language-ID changes ripple into sley.
